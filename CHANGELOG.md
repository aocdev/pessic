## [1.0.0] - 2026-11-11

First release of the desktop app: a port of the Pessic web app (PWA) to Java 21 and JavaFX, with an
embedded SQLite database. Built between 2026-11-09 and 2026-11-11, in the four steps below. Each one
upgraded the database schema (`PRAGMA user_version`) and backed up the old file as
`pessic.db.bak-v<n>` first.

### Added

#### Desktop port of the web app (schema 1)
- Maven modules `pessic-core` (rules, no dependencies), `pessic-db` (SQLite, migrations, JSON) and
  `pessic-app` (JavaFX).
- Profiles with income, automatic savings, payday and household; several profiles per database.
- Pay cycles from payday to the day before the next one; after the 15th the cycle takes the next
  month's name.
- Category envelopes with limits, fixed monthly payments (with start/end month and one-off "extra"
  payments added to their category's limit), and annual payments funded by a monthly reserve.
  Ending a fixed payment from a given month ("Ja no el pago des de …") keeps earlier months intact.
- Payment plan with running balance, "Pagat" / "Desfés", "Pagat amb la reserva" for annual payments.
- Weekly limits that carry over unspent or overspent money; money left per day; pace status.
- Import of the web app's JSON backup; JSON and CSV export (Excel/LibreOffice friendly: `;`,
  decimal comma, `dd/MM/yyyy`, UTF-8 BOM, formula injection neutralised).
- Parity tests against the original JavaScript formulas (`tools/js-oracle.js`, golden file).

#### INE categories and limits (schema 2)
- The 13 COICOP 2018 groups that INE uses in the Encuesta de Presupuestos Familiares, with Catalan
  names, descriptions and examples as help in every category picker.
- INE reference data (EPF 2025) bundled and generated by `tools/ine/fetch_epf.py`.
- Proposed limits from INE averages for the household type, size and income band, net of what the
  annual reserve covers and scaled to fit the income. INE marker on every envelope.

#### Monthly budget management (schema 3)
- Extra incomes (extra paycheck, bonus, other) with a destination chosen each time: this month's
  budget, the annual reserve, a savings goal or savings. Refunds that go back to their category.
- 12 or 14 paychecks a year as an editable setting; the expected extra paycheck appears in its cycle.
- Annual reserve with a real balance (opening balance, contributions, withdrawals, adjustments) and
  the first month it would fall short.
- Savings goals ("guardioles") with target, date, monthly amount, progress and archiving; expenses
  can be paid from a goal or from the reserve without using the month's budget.
- Month close: posts contributions, sends the leftover to savings, the next month, the reserve or a
  goal, and stores a snapshot with that month's limits. "Reobre" undoes it.
- "Històric" tab: up to 12 months as a chart and a table, per-category history against limit and INE,
  CSV export.
- "Propers pagaments" on Resum: fixed payments overdue or due within 3 days, annual payments and the
  extra paycheck of the month, reserve shortfall.
- Movement search: text (accent-insensitive), category, type and period, with totals.
- Daily automatic backups (`VACUUM INTO`, newest 10 kept), backup now, and restore that saves the
  current data first.
- JSON backup format v3.

#### Payroll account balance (schema 4)
- The balance of the account where the salary arrives, given once (first-run form, Resum or
  Configuració) and estimated from then on: salary in, automatic savings and reserve/goal transfers
  out on payday, expenses not paid from a pot out, incomes that stay in the account in.
- "Al compte avui (estimat)" and "Abans de tornar a cobrar" on Resum, with a warning when the
  balance would go below zero before payday.
- "Pagaments fixos" shows the forecast balance after each pending payment and marks the ones that
  do not fit ("sense saldo").
- "Ajusta amb el banc", and an optional bank balance check at month close; the difference appears as
  "Dif. banc" in Històric and in the history CSV.
- Offer to move money already in the account into the reserve (prefilled with what covers the next
  12 months of annual payments) and goals.
- JSON backup format v4 (v1–v3 still import).

#### Project
- Open source under the Apache License 2.0 (`LICENSE`, `NOTICE`), with `CONTRIBUTING.md`,
  `CODE_OF_CONDUCT.md`, `SECURITY.md`, issue and pull request templates, a CI workflow, and the Maven
  Wrapper (`./mvnw`).
- Installers built with `jpackage` (`packaging/package.sh`): `.rpm` and `.deb` for Linux, `.msi` for
  Windows, `.dmg` for macOS, each with its own Java runtime, so Java does not need to be installed.
  `.github/workflows/installers.yml` builds all of them on GitHub Actions and attaches them to the
  release of a `v*` tag.
- `README.md` for developers, `MANUAL.md` (user manual, Catalan), `WHATS_NEW.md` and this changelog.
- `.gitignore` that keeps databases, backups, exports, spreadsheets, logs and IDE files out of the
  repository.

### Changed
- Every user-visible text moved out of the code into `i18n/strings_ca.properties` (about 615 keys), read
  through `I18n.t(key, values…)` and `I18n.plural(key, n)`. Only Catalan for now; the screens show exactly
  the same text as before. `I18nTest` keeps the code and the file in step.
- Category names, descriptions and examples, income and leftover labels, household types and CSV headers
  also come from the strings file.
- Texts the user sees no longer mention the old web app: the first-run screen offers to import "una
  còpia de Pessic", and the manual and release notes no longer refer to it.
- Code organised by feature instead of one package per module: `budget`, `expense`, `payment`,
  `income`, `savings`, `account`, `monthclose`, `history`, `profile`, `ine`, `export` and `common`,
  with the same names in `pessic-core`, `pessic-db` and `pessic-app`. Tests sit next to the feature
  they test.
- `ProfileOps` split into one operations class per feature (`ExpenseOps`, `PaymentOps`, `BudgetOps`,
  `IncomeOps`, `SavingsOps`, `AccountOps`).
- `ProfileRepository` split into one store per feature (`ExpenseStore`, `PaymentStore`,
  `BudgetStore`, `IncomeStore`, `SavingsStore`, `MonthCloseStore`, `AccountStore`) on top of a shared
  `Jdbc` helper; the repository keeps the profile row and saves everything in one transaction.
- Test data replaced with an invented profile; the golden file was regenerated from it.

### Fixed
- The cycle dates in the header said "Del 28 de octubre"; now "Del 28 d'octubre".
- "1 dies" left in the month on Resum; now "1 dia".
- Dialogs opened squashed because their height was measured before styles were applied.
- The month-close banner text was cut off on narrow windows.
- Històric listed months before the first data, and showed the running month as "100 %".
- Long category names squeezed the concept column in "Pagaments fixos".

### Decided against
- **Bank statement import** (Sabadell and Mediolanum `.xls`, Revolut `.csv`). It would need Apache
  POI and a preset per bank, and it serves account analysis rather than budgeting. Pessic only needs
  the balance of the payroll account, which the user gives.

### Known differences from the web app
- Fixed payments due on the same day are listed alphabetically; the web app lists them in the order
  they were created. Totals are the same; only the running balance between those lines differs.
- Backups in format v4 cannot be opened by the web app.
